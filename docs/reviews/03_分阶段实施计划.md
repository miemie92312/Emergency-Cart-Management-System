# 实施计划 R2：先 Prototype，再 Demo 与 MVP

日期：2026-11-07。依据：[当前 PRD](./00_PRD_V0.1_修订稿R1.md)、[审查证据](./01_项目审查报告.md)、[数据契约](./02_数据模型与迁移设计.md)。本计划替代原 S0–S9 管理安排。

**当前执行独立 Prototype：五页流程、内存模拟、可点击交互，不改旧项目代码，不接真实数据库。M0 数据安全修复授权保留，暂不执行。** 对外交付按 Prototype→Demo→MVP；下文 M0–M4 保留为工程检查参考，不是五次独立产品交付或框架升级承诺。以下仓库路径仍是未来计划，未开始开发。

## 1. 路线与管理边界

**当前 Prototype → M0 原生安全修复 → M1 数据模型与业务测试 → 复用原生项目做核心 Demo → 按需完善与个人 MVP 验证。** Vue 仅在页面/动态配置复杂度实际阻碍迭代时引入，不作为 Demo 前提。

- M0 不搭 Vue/Vite 工程、不换库、不实现多车；M1 先验证数据契约与迁移，再做业务页面。默认优先原生实现，确需迁移时才逐块替换，禁止一次重写。
- M2 核心任务能操作后即可获取使用者反馈，不等 M3 全做完。H5 与 PWA 安装态的验证结论分开。
- 二维码移出首版，不开发、不引入 qrcode.vue，不设二维码发布门槛；车列表和独立详情仍保留。
- JSON 从 M0 起保障，M1 验证新模型完整恢复，M3 只完善使用体验；新数据启用前必须已有救援路径。
- 用小提交和一份实施记录管理，不要求每个模块再建一组计划、审批与交付文档。保留必要测试、数据可信边界和回滚。
- 不增加后端、账号、同步、AI 或未经医院确认的临床默认配置。不把已批准的 M0 扩大为后续功能授权。

## 2. M0：旧项目安全修复（已批准，当前未执行）

目标：处理现有数据丢失、错误成功提示、批量登记误导与导入注入风险，保留原生实现。

| 拟修改文件 | 边界 |
|---|---|
| `index.html` | 事务封装、导入校验与原子恢复、一致性快照导出、ID 安全输出、批量入口语义、演示标识 |
| `sw.js` | 仅处理本次补丁缓存版本与受控更新，不引入新 PWA 架构 |
| `README.md` | 备份恢复、旧检查未知、演示与本次修复范围 |
| `tests/legacy-safety.*`、`tests/fixtures/legacy/*.json` | 最小自动回归与合成备份，不为测试先搭完整前端工具链 |
| `docs/implementation-log.md` | 一份持续更新的基线、改动、验证、问题与回滚记录 |

修复内容：

1. request success 不再等同写入成功，以 transaction.oncomplete 为准，abort/error 不误报；不提前替换内存状态或关闭表单。
2. 兼容旧外层/裸 JSON，完整检查版本、数组、ID 类型与重复、数量、日期和设置。非法值列明原因，不静默取整、补日期或改成零。未知字段不执行，不无声丢弃，应保留或明确阻断。
3. 导入经预览、恢复前备份提示和二次确认，在同一多 Store 事务替换 drugs/checks/settings；失败回滚。导出从单个只读事务读取完整快照，避免使用过期内存数组。
4. 同时校验主键和安全输出属性，保留合法历史主键，不以非 UUID 为由拒绝所有兼容数据。
5. 暂停原“一键生成整批检查”的提交路径，提示逐项登记；不先开发待检队列。旧记录只标已有登记、结果/方式未知，不补正常、不按时间猜批量。
6. 新载入示例有持久用途标记和持续提示，不改原示例药品/规格/数量来伪装医院模板。已有混合数据用途不自动认证。
7. 保留旧库和三个 Store、旧备份能力，不引入 Cart/ItemBatch 或新格式迁移。年月精度完整支持在 M1/M2；M0 遇旧契约不能解释的年月输入须明确阻断并保持原库，不补月末。

验收：正常旧备份可恢复；坏的第二条记录、重复 ID、事务中止、取消或容量失败后旧库完整不变；设置按明确恢复语义处理；导入 ID 不产生额外 HTML 属性；批量点击不新增整批检查；示例提示不消失；原 CRUD、搜索、效期和备份不退化。

测试：合成临时库做恢复前后全表比较、request success→abort、空库/空备份、设置替换、孤立历史保留、双击和 JSON 往返；纯校验用最小自动化，事务在真实浏览器验证，mock 不包办。检查旧 SW 客户端可取得补丁，不强刷未保存表单。不得对真实工作库故障注入。

风险/回滚：单文件事件绑定与旧缓存可能回归，分小提交验证。固定源码起点、留独立旧 JSON；回退静态代码不清库、不自动恢复旧快照。原物理库版本不变。归档系统、多车、临床配置及 Vue 全面迁移不属于 M0。

## 3. M1：核心数据架构（后续规划）

目标：先证明数据模型、规则与恢复，再写新业务页面。

拟新增/修改：`src/domain/{models,schemas,expiry,quantity,inspectionRules}.ts`、`src/data/{db,legacyReader,migration}.ts`、`src/services/{backup,restore}.ts`、`tests/{domain,migration,restore}/*`；按需建立 TypeScript/Zod/Vitest/Dexie 配置与锁文件。不创建完整 Vue 页面或模板设计器。

验收：

- Cart、CartItem、ItemBatch、InspectionRecord、StockChangeRecord 能表达核心业务；跟踪批次时总数只来自批次。quantityPrecision=0，未知/零数量、应有量/旧阈值分开。
- expiryPrecision 与原值匹配；合法年月只存原值并标规则待确认，不补日/算倒计时。非法日期和精度不符被识别。
- 新检查时间由设备生成，不开放手改；旧 timeSource=unknown、recordedAt 未知不填迁移时间；设备必检未全正常不能整体正常。
- 旧库/两种旧 JSON→新格式往返；原始字段、孤立历史可追溯；不补正常、不猜示例、不合并同名物品。迁移幂等、中断可重试、目标非空不自动合并。
- 新模型完整 JSON 和原子恢复已通过；模板表与编辑器留 M3，不要求一次建齐未来 Store。

测试：日期/闰年/夏令时/年月、整数与非法数值、设备缺项/异常/不适用、旧主键/外键/重复迁移/未知版本、完整 JSON 回读和恢复失败。fake-indexeddb 供自动化，真实浏览器补充事务、版本、关闭页面和容量错误。

风险/回滚：旁路新库占额外空间，不承诺跨库原子；停止旧客户端写入、取一致快照并校验。M1 仅在隔离环境演练，通过不代表自动获准切换工作库。模型问题在写 UI 前修正。

## 4. M2：核心 Demo，优先复用原生实现（后续规划）

目标：使用者能完成“选车→看异常→逐项检查→使用/补充→留痕”，尽快获得操作反馈。

优先在原 `index.html` 及按需要提取的原生业务/存储模块完善流程，保留统一存储边界和任务链测试。若复杂度达到需迁移的程度，再采用此前列出的 `src/main.ts`、App/视图/字段组件等 Vue 路径；不预先批量创建这些文件，不因多车而强制引入 Vue Router。

验收：多车隔离；复制仅配置、库存未知、检查为空；四类物品固定字段区和空科室入口；多批次、年月精度、效期与数量提醒；单项明确确认、时间来源、设备必检及历史快照；数量更新和记录原子保存；补充后待复核，不能自动正常。提供完整 JSON 救援入口；Excel 为 Demo 的 P1，不以它阻碍核心任务初评。

测试：完整任务链、跨车同名物品、部分检查退出、多异常、设备缺项目、前台切回/跨日、零量与未知、另一窗口改库存、双击和事务失败。在目标手机 H5 做早期操作评估，未验证平台明确记录，不以桌面 E2E 代替手机结果。

风险/回滚：不维护两份库存真源；若迁移 Vue，新旧渲染不操作同一节点。切换工作库先经 M1 校验；有新版编辑后先导出新版完整备份，不能回旧前端就称全部数据已恢复。单项确认的必要操作不能靠批量伪造优化。不加入二维码或 Pinia，不把其他物品扩成低代码平台。

## 5. M3：产品完善（后续规划）

目标：补充试用需要的基础配置、可阅读导出和安装体验。

拟新增/修改：空模板数据、`src/views/{TemplateList,TemplateEditor}.vue`、`src/components/fields/{CustomFields,FieldRenderer}.vue`、`src/components/templates/*`、`src/services/excelExport.ts`、备份恢复界面、`src/pwa/*`、图标和 Vite PWA 配置、对应测试与依赖声明。SheetJS CE、vite-plugin-pwa 在本阶段加入。

验收：空科室入口与用户配置可复制；仅文本/数字/日期/备注四类字段；字段 ID 稳定，改类型不损坏旧值，模板变化不追溯改车与历史。Excel 四 Sheet 正确，年月精度保留、倒计时留空/待确认、旧结果不变正常，批号与公式符号文本正确。生产构建离线资源就绪后可操作和导出；提示更新不强刷表单，旧 SW 交接不删库；说明本机与备份，不暗示云同步。每次新依赖核对实际版本、完整性、转依赖及 LICENSE/NOTICE，Pinia/qrcode.vue 继续暂缓。

测试：四字段 JSON 往返、非法输入、模板复制隔离/改名/归档；XLSX 回读及实际 Excel/WPS 等打开，覆盖空表、中文、前导零、长文本与公式符号；手机性能；生产构建离线、旧 SW 升级、多标签/草稿中更新和回滚。测出阻塞才考虑 Worker，不预建性能架构。

风险/回滚：配置编辑器不得再扩成低代码平台，改动围绕观察到的问题。导出/PWA 可分别回退，JSON 救援始终保留；安装能力到 M4 实测后才能宣称支持。

## 6. M4：实机与用户验证（后续规划）

目标：用真实操作决定下一步，不以技术或文档数量衡量成功。

拟修改：实测问题对应的源文件/测试、README 支持范围；继续更新同一实施记录，可附一份简短试用记录，不建设十套验收文档。

验收：Android Chrome、iOS Safari、Android 安装态、iOS 主屏幕分别留证据，覆盖键盘、年月/日期录入、弹窗滚动、safe-area、离线/后台切回、逐项检查、使用补充、导出与从文件独立恢复。目标使用者完成任务，记录卡住、误解、遗漏、耗时与反馈；开发者不代操作后宣布可用。缺设备/未过项如实标未验证。

测试：先合成数据，再按医院确认范围使用真实配置；不公开上传配置、检查人或备份。与原流程比较时说明任务、参与人数和方法，不套用论文收益、不宣称临床效果。M2 起可提前反馈，M4 负责系统收口。

风险/回滚：个人设备限制、不愿维护第二份账、本地模式不适合交接均可能推翻假设。先调整范围与交互，不自动加后端、登录或同步。发布/真实场景使用与代码开发授权分开。
