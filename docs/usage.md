# 运行、备份与发布

## 先体验

首次运行是空白库；可以新建空车，也可以在配置中显式创建演示车。示例名称与数量均为合成数据，不是临床配置。工作 Demo 与低保真原型分别位于根入口和 `/prototype/`。

`npm ci → npm run dev` 用于开发。`npm test → npm run build → node scripts/serve.mjs` 用于本机生产预览，默认 4173，端口可传 `--port 4181`。双击“打开产品.cmd”会检查构建目录后运行同一个静态服务，关闭终端即停止。

## 保留自己的数据

1. 在原来使用的浏览器、域名、端口与入口打开旧站，先导出 JSON 并另存。
2. 原站同 origin 更新后，可在配置“查找本浏览器旧版数据”只读预览原 `RescueCartDB`。不同 origin 无法直接读旧数据，请使用文件恢复。
3. 恢复会替换当前新库的完整数据集，不会自动合并。先导出当前库，核对条数与来源，再确认覆盖。旧库不删除。
4. 恢复失败保留原数据；成功覆盖后，可从“恢复上次覆盖前数据”回退最近一次。这个快照仍在同一浏览器，清理站点数据也会丢失，不能替代外部备份。
5. XLSX 供阅读整理，只导出四张业务阅读表；它不是完整恢复文件。全部检查、变化、扩展配置与旧归档以 JSON 为准。

JSON 的 SHA-256 是损坏检测，不是加密或来源认证；当前备份文件包含配置和用户填写的检查人，应按自己的保管要求保存，不上传公开仓库。本项目交付包不包含运行时备份与浏览器数据。

## 静态部署

将 `npm run build` 生成的整个 `dist` 上传到 HTTPS 静态空间即可，无需业务服务。默认相对 base，支持项目子路径。保留 `sw.js`、workbox 文件、图标、manifest 与全部哈希资源，避免只上传 index.html。

仓库 `.github/workflows/pages.yml` 为手动部署工作流：仓库 Settings → Pages 将 Source 设为 GitHub Actions，再在 Actions 中运行 Deploy static site to Pages。只有运行成功并取得实际 URL 后，才能将该链接作为 HR 公开体验入口；未运行前不要承诺 URL 可用。CI 的 Tests and build 会检查主分支提交。

本轮另外提供所有者私有预览（若交付消息附链接）；托管访问限制与产品业务登录无关，不能把私有预览发给未授权 HR 当成公开体验地址。

## PWA

通过 HTTPS 或本机 localhost 打开生产版，在配置中确认“离线资源已就绪”后再测试断网。数据始终在本机 IndexedDB，不随 PWA 缓存上传。更新有提示，请先保存表单，再主动更新；不是无提示刷新。

- Android：支持时使用安装提示或浏览器“安装应用 / 添加到主屏幕”。
- iOS：使用 Safari 的分享菜单“添加到主屏幕”。实际入口间存储是否共享须在目标系统验证，不能承诺所有系统相机/浏览器/PWA 都读取同一份数据。
- 清理站点数据、更换浏览器、设备或 origin 会造成独立数据环境；无自动同步。持久化申请可能被浏览器拒绝，定期下载 JSON。

本轮桌面缓存验证通过，Android/iOS 真机、飞行模式、系统回收等仍在待验证清单中。
